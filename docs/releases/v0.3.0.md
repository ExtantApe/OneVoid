Works with Posse 0.11.0 (formerly Mayor); the Mayor name is no longer recognized (D196, D292).

## What changed

- Island travel and team invites read circles from the permission nodes `posse.circle.<name>`. The old `mayor.circle.<name>` nodes are not circles, so they connect nobody.
- With no Posse, or no circles, island travel and team invites still answer no. The startup note now says "No Posse circles exist, so island travel and team invites are off."
- The soft dependency in `paper-plugin.yml` is now `Posse`. Config comments, command messages and the README use the new name. No config key changes.

## Installing over 0.2.0

Install Posse 0.11.0 at the same time, and rename its permissions first as Posse's release notes describe. With the server stopped, swap in `OneVoid-0.3.0.jar`.

## Tested

Unit tests, including that only `posse.circle.<name>` nodes are circles and `mayor.circle.<name>` ones are not. Bots with the real Posse 0.11.0 jar on throwaway Paper servers: the `travelAndTeams` section passed on 26.2 (19/19 on its own run, with kids in one circle, an adult in the other, travel and team invites), and 26.3 passed its server-only checks (5/5). The full 26.2 run had 70 passes and 2 failures: `travelAndTeams` timed out waiting for a teleport once (it passed on its own rerun), and `crashes` (kill -9 around a death and the way bell) failed on its own rerun too. `crashes` doesn't touch circles, but I haven't shown it fails on the previous version, so treat it as unexplained. Not yet seen in a real game client.
